## Changes detected — CODE UPDATED

### 1. Warehouse entries (Types 21 and 22) excluded from CAPE — effective July 7, 2026

**Source**: CSMS #69127837; GHY advisory

Effective July 7, 2026, CBP no longer accepts warehouse entry types 21 and 22 on CAPE Declarations. Any Type 21/22 submission on or after that date is rejected with `ENTRY TYPE NOT ALLOWED`.

**Warehouse withdrawals (Types 31, 32, 34, 38) remain eligible** — IEEPA duties are paid at withdrawal, not at warehousing, so the refund attaches to the withdrawal entry.

**Transition risk**: Warehouse entries (21/22) accepted on CAPE Declarations between April 20 and July 6, 2026 WITHOUT a corresponding withdrawal submission will NOT be (re)liquidated with an IEEPA refund. Importers in this position must file a new CAPE Declaration covering the withdrawal entries.

**Code change made**: Added `"21"` and `"22"` to `EXCLUDED_ENTRY_TYPES` in `src/lib/tariff-calculator.ts`. The `excluded_type` reason string now includes actionable guidance to re-file using withdrawal entries.

### 2. CAPE Phase 2 launched June 29, 2026

**Source**: Multiple law firm advisories; CSMS announcements

Phase 2 expanded CAPE to cover entry types 01, 02, and 06 that are **flagged for reconciliation where the Type 09 reconciliation entry has NOT yet been filed**. Previously these were excluded from Phase 1 due to the timing uncertainty of pending reconciliation.

Key constraints that still apply:
- Entries must still be unliquidated or liquidated within the 80-day window
- If the Type 09 reconciliation entry HAS been filed, the entry remains excluded
- Type 09 entries themselves remain excluded from CAPE
- Estimated Phase 2 coverage: ~2.8 million additional entries / ~$28.7 billion in potential refunds

**Code change made**: Added `isFlaggedForReconciliation?: boolean` field to `EntryForEligibility` and added `cape_phase2` to the `FilingMethod` union type. The `checkEligibility()` function now returns `filingMethod: "cape_phase2"` for reconciliation-flagged entries.

## Changes detected — NO CODE CHANGE REQUIRED

### 3. CAPE Phase 3 expected end of July 2026

**Source**: Green Worldwide Shipping (citing June 9, 2026 CIT hearing testimony)

Phase 3 will cover **finally liquidated entries** — those liquidated more than 80 days before the CAPE filing date, which currently fall in the "protest" or "litigation" buckets.

**Critical restriction**: Phase 3 refunds will be processed only for importers who have **filed lawsuits at the CIT**. Importers who have not filed suit and whose protest windows have closed are not covered.

**Impact on calculator**: When Phase 3 launches, the `"litigation"` filing method bucket may need to split into `cape_phase3` (CIT plaintiffs) vs. `litigation_no_path` (non-plaintiffs with expired protests). No code change until CBP publishes the official Phase 3 CSMS with exact scope.

### 4. Government appealing CIT refund order to Federal Circuit

**Source**: Holland & Knight (June 2026)

The government has appealed the CIT order mandating IEEPA duty refunds to the Federal Circuit Court of Appeals. This introduces legal uncertainty — Phase 3 scope and the refund program as a whole could change if the government prevails. The CAPE program continues to operate under the existing order while the appeal proceeds.

**Impact**: No code change. Attorneys cannot file CAPE declarations (only IOR or original licensed broker can). If the government wins the appeal and the refund order is stayed or reversed, CBP would announce via CSMS.

### 5. Rejection rate update

**Source**: Web search aggregation

Early Phase 1 data (as of April 26, 2026, ~6 days after launch) showed approximately 63% of entries passed the first validation step, suggesting a ~37% initial rejection rate. The previously tracked 15% figure (CBS News) likely reflects later-cycle data after common errors were corrected.

**Most common rejection error codes** (unchanged from prior monitoring):
- `ENTRY ON DRAWBACK`
- `PROTEST ON ENTRY`
- `ENTRY SUMMARY UNDER REVIEW`
- `NO IEEPA HTS ON ENTRY`
- `STATEMENT PROCESSING NOT COMPLETE`
- `ENTRY TYPE NOT ALLOWED` (now also triggered by Types 21/22)

### 6. Multi-IOR broker CSV gotcha — active operational risk

**Source**: Web search; trade practitioner advisories

CAPE's validator silently processes only the first IOR's entries when a CSV contains entries from multiple Importers of Record. No error is returned — entries for the second and subsequent IORs are simply ignored.

**Correct practice**: Submit a separate CAPE Declaration CSV file for each IOR, even when the same broker holds power of attorney for all of them. This is not documented in the official CBP guidance but is consistently reported by practitioners.

**Impact on calculator**: `generateCapeCsv()` currently batches all eligible entries into one CSV per 9,999-entry limit. If this tool is used by a broker filing for multiple IORs, callers must ensure they pass only entries belonging to a single IOR. No code change made — this is a caller responsibility, but worth noting in broker-facing UI copy.
