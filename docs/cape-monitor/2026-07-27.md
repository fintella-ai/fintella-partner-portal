## CAPE Phase 2 — What Changed (June 29, 2026)

### New Eligibility: Reconciliation-Flagged Entries

Entry types **01, 02, and 06** that are flagged for reconciliation are now CAPE-eligible in Phase 2, **provided the Type 09 reconciliation entry has not yet been filed**.

**Critical rule:** CAPE declaration must be filed **before** the Type 09. Filing the reconciliation entry first permanently locks the underlying entries out of CAPE Phase 2. This is not recoverable in the current phase.

**CBP 30-day guidance:** If the reconciliation filing deadline is within 30 days, CBP advises prioritizing the reconciliation entry over the CAPE declaration (the refund opportunity is sacrificed to avoid a missed reconciliation deadline, which carries its own penalties).

### Phase 2 Scope Limits

- Same 80-day liquidation window as Phase 1 (unliquidated + liquidated within 80 days)
- Still **excluded**: Type 08 (duty deferral), Type 09 (reconciliation entries themselves), Type 23 (TIB), Type 47 (drawback), surety-paid entries, warehouse withdrawals, entries with pending AD/CVD instructions

### Scale

CBP reported roughly $28.7 billion in additional refunds tied to ~2.8 million entries now covered by Phase 2, on top of ~$95 billion already accepted into CAPE as of early June.

## Rejection Trends (Phase 1, as of late June 2026)

- **Overall rejection rate**: ~15% (CBP confirmed)
- **Flexport audit**: ~20% error rate in entries filed by other brokers
- **Single most common error**: FTZ Type 06 HTS sequence mismatch — CAPE validator reads entry summary line-by-line and rejects if the base HTS classification and the IEEPA Chapter 99 line can't be reconciled
- **Other common errors**: HTS classification mismatch, valuation inconsistency, country-of-origin discrepancy, Section 232/301 stacking errors, `ENTRY ON DRAWBACK`, `PROTEST ON ENTRY`, `ENTRY SUMMARY UNDER REVIEW`

## ACH Enrollment (No Structural Change)

- Refund-specific ACH enrollment in ACE is required — having ACH set up for duty payments is **not** sufficient
- As of CBP's May 12, 2026 CIT declaration: 1,880 consolidated refund batches stuck; 9,837 individual refunds untransmitted to Treasury due to missing ACH account info
- No new enrollment process announced — same requirement, higher visibility

## Code Changes Made

### `src/lib/tariff-calculator.ts`

1. **`EntryForEligibility` interface** — added three new optional fields:
   - `isFlaggedForReconciliation?: boolean` — flags an entry type 01/02/06 awaiting Type 09
   - `hasType09Filed?: boolean` — if `true`, entry is locked out of CAPE Phase 2
   - `reconciliationDeadlineDays?: number` — days until recon deadline; triggers review flag if ≤30

2. **`FilingMethod` type** — added `"cape_phase2"` to distinguish Phase 2 reconciliation filings (same ACE portal, but different eligibility path and filing-order risk)

3. **`EligibilityResult.status`** — documented new `"excluded_reconciliation"` status value

4. **`checkEligibility()` function**:
   - Step 4a: if `isFlaggedForReconciliation && hasType09Filed` → `excluded_reconciliation`
   - Phase-aware filing method: reconciliation-flagged eligible entries use `"cape_phase2"` instead of `"cape_phase1"`
   - New `applyReconciliationReviewFlag()` helper: sets `needsReview: true` + `reviewNote` when reconciliation deadline ≤30 days

5. **`EXCLUDED_ENTRY_TYPES` comment** — updated to document Phase 1 vs Phase 2 scope

### `src/lib/tariff-risk-score.ts`

6. **`FILING_RISK` record** — added `cape_phase2: 5` (slightly higher than Phase 1's `0` due to filing-order sensitivity)
