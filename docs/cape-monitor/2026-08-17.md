## 1. CAPE Phase 2 — Launched June 29, 2026

**Source**: Multiple trade publications (Thompson Hine SmarTrade, Diaz Trade Law, M.E. Dey & Co., TariffsTool.com)

### What changed

Phase 2 of CAPE became live on **June 29, 2026** and adds eligibility for **reconciliation-flagged entries**:

- Entry types **01, 02, and 06** that are flagged for reconciliation are now accepted via CAPE, provided the corresponding **Type 09 reconciliation entry has NOT yet been filed**.
- The CAPE process removes IEEPA duties from the flagged entry *prior* to the filing of the reconciliation entry, separating the IEEPA refund from reconciliation math.
- Eligibility window: entries must be unliquidated, or if liquidated, within 80 days of liquidation.

### What is still excluded in Phase 2

- Reconciliation-flagged entries where the **Type 09 has already been filed** — locked out.
- Entry types other than 01/02/06 with reconciliation flags — not eligible.
- Type 47 drawback entries — still excluded; no phase covers them yet.

### Code changes made

- Added `cape_phase2` to the `FilingMethod` union type.
- Added `isFlaggedForReconciliation?: boolean` field to `EntryForEligibility` interface.
- Added Phase 2 check in `checkEligibility()` (step 4a): reconciliation-flagged types 01/02/06 are now routed to `"eligible"` with `filingMethod: "cape_phase2"` and a `needsReview` flag prompting verification that Type 09 hasn't been filed.

### Remaining watch items (Phase 3)

On **July 17, 2026**, CIT Senior Judge Eaton ordered CBP to reliquidate finally-liquidated entries (>180 days, historically locked) — but **only for importers who are plaintiffs** in the 3,700+ CIT cases. The code's existing `filingMethod: "litigation"` path is still the correct routing for entries beyond the protest window. No code change needed yet.

## 2. Warehouse Entry Types 21 and 22 — Removed from CAPE (July 7, 2026)

**Source**: CBP CSMS #69127837; Alba Wheels Up, Sobel Network Shipping, multiple broker advisories

### What changed

Effective **July 7, 2026**, CBP stopped accepting warehouse *storage* entries on CAPE declarations:

- **Type 21** (Warehouse Entry) — rejected with `ENTRY TYPE NOT ALLOWED`
- **Type 22** (Re-warehouse Entry) — same

**Why**: IEEPA duties on warehoused goods are assessed at the time of *withdrawal*, not at initial warehouse storage. Filing on the warehouse entry was structurally incorrect — the duty refund should be claimed on the withdrawal entries.

**What remains eligible**: Warehouse *withdrawal* entries (Types 31, 32, 34, 38) — unchanged, still accepted.

**Transition issue**: Warehouse entries that were *accepted* on CAPE declarations between April 20 and July 6 *without* a corresponding withdrawal submission will **not** be reliquidated with an IEEPA duty refund under the current framework. Brokers need to file a separate CAPE declaration for the withdrawal entries.

### Code changes made

- Added `"21"` and `"22"` to `EXCLUDED_ENTRY_TYPES` (previously only `["08", "09", "23", "47"]`).
- Updated the `checkEligibility()` "excluded_type" message for Types 21/22 to explain the warehouse-vs-withdrawal distinction and direct the broker to file against withdrawal entries instead.
- Added a detailed JSDoc comment on `EXCLUDED_ENTRY_TYPES` documenting when each type was excluded and why.

## 3. New ACE Report: ES-022 (CAPE Entry Summary Report)

**Source**: CBP CSMS #68536553; CAPE Portal Guide, Liberty Justice Center

### What was found

A new ACE report **ES-022** (CAPE Entry Summary Report) is now available. It was not in the original list of tracked reports. Its function:

- Links CAPE declaration number → underlying entry numbers → refund numbers
- Shows **approved refund amounts**, separated into **principal** and **interest** components
- Acts as a dashboard to confirm whether specific entries have been processed and approved

The existing REV-603, REV-613, REV-615 reports are unchanged in function. No code change needed — ES-022 is read-only reporting for filers. Worth documenting for broker training materials.

**Full tracked ACE reports for CAPE (updated)**:

| Report | Name | Function |
|--------|------|----------|
| ES-022 | CAPE Entry Summary Report | Links claim → entries → refund amounts; principal vs. interest split **(new)** |
| REV-603 | Trade Refund Report | Pending and successful refunds |
| REV-613 | ACH Rejected Refunds Report | ACH failures (1,880 batches stuck as of May 12 — IOR ACH info missing) |
| REV-615 | CAPE Details Refunds Report | CAPE-specific; ties to claim number; entry-level status |
| ES-701 | Liquidation Notice | Per entry |
| ES-702 | Bulk Liquidation Notice | — |

## 4. CBP Position Reversal on Historically-Liquidated Entries

**Source**: Sheppard Mullin (NatLawReview), BDO, Davis Wright Tremaine; May 29, 2026

### What happened

On **May 29, 2026**, CBP filed a motion asserting it **lacks legal authority** to issue refunds on finally-liquidated entries (>180 days past liquidation) without an importer-specific court judgment. This is a reversal from the initial CIT March 4, 2026 order's implication of universal refund coverage.

### Impact on the calculator

The code's existing `filingMethod: "litigation"` path for entries liquidated >180 days ago is **correct** — that path already tells brokers legal action is required. The status quo language holds:

> "Protest window expired (liquidated > 180 days ago) — CIT litigation only"

No change needed. However, the note for broker-facing UI should emphasize that CBP's own position is that these require individual lawsuits, not just participation in the general class.

## 5. Rejection Rate — Unchanged at ~15-19%

**Source**: TariffsTool.com; multiple broker advisories

No change from last known rate. Top rejection codes remain:
- `ENTRY ON DRAWBACK`
- `PROTEST ON ENTRY`
- `ENTRY SUMMARY UNDER REVIEW`
- `NO IEEPA HTS ON ENTRY`
- `STATEMENT PROCESSING NOT COMPLETE`

**New finding**: CBP brokers filing on behalf of **multiple IORs** are experiencing silent rejections when a single CSV contains entries from different IORs. Each CAPE declaration must be scoped to a single IOR. The `generateCapeCsv()` function does not enforce this — worth adding a validation check or at minimum a warning in the UI.

## 6. ABI / Filer Eligibility — No Changes

Confirmed unchanged:
- Filing channel: ACE Portal only. ABI still not supported.
- Filer eligibility: IOR or the original licensed customs broker who filed the entries. Attorneys still cannot file.
- CSV format: Single column `Entry Number`, no header change.
- 9,999 entry limit per declaration: unchanged.
