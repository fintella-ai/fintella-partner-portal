## 2. CAPE Phase 2 — LAUNCHED TODAY

**Source**: CSMS #69035485 (June 23, 2026); effective **June 29, 2026**

### What Phase 2 covers

Entry types **01, 02, and 06** that are **flagged for reconciliation**, but only when:
1. The corresponding reconciliation entry (Type 09) has **not yet been filed**
2. The entry is unliquidated OR liquidated within the 80-day window (same scope as Phase 1)

### Critical filing sequence

> File the CAPE declaration **FIRST**. Once the Type 09 reconciliation entry is filed, the underlying entries are **permanently locked out** of CAPE Phase 2.

Correct sequence: CAPE Declaration → (CBP strips IEEPA duties from flagged entries) → File Type 09 reconciliation.

Wrong sequence: Type 09 first → underlying entries locked out of Phase 2, no IEEPA refund via CAPE.

### What Phase 2 does NOT cover

- Type 09 entries (reconciliation entries themselves) — future phase TBD
- Entries flagged for reconciliation **with a Type 09 already on file** — future phase TBD
- Type 47 (Drawback) — future phase TBD
- Type 08 (Duty Deferral) — future phase TBD
- Type 23 (Temporary Importation Bond) — future phase TBD
- Historically liquidated entries beyond the 80-day window — Phase 3 (CIT litigants only)
- Entries with pending AD/CVD instructions — Phase 1 exclusion unchanged

## 3. CAPE Phase 3 — Expected Late July 2026 (CIT Litigants Only)

**Source**: Multiple trade publications + government appeal filing

Phase 3 will cover **finally liquidated entries** (past the 80-day window), but the government has stated that Phase 3 refunds will be processed **only for importers who have filed lawsuits at the CIT**. Non-litigants will not receive Phase 3 refunds through CAPE.

> **Implication for Fintella clients**: Any client with entries liquidated >80 days ago who has not filed a protective CIT action will be locked out of Phase 3. The only path is formal protest (if within 180 days) or CIT litigation. Brokers should advise clients urgently.

## 4. Government Appeal of CIT Refund Order

**Source**: Holland & Knight, Jackson Walker, Foley & Lardner, DWT (June 2026)

On **June 2, 2026**, the DOJ filed a Notice of Appeal to the U.S. Court of Appeals for the Federal Circuit challenging the CIT's universal IEEPA tariff refund order.

### Key arguments

- CIT's refund order constitutes an impermissible universal injunction extending relief to importers who did not file protective CIT actions
- Government claims the CIT lacks authority to require CBP to issue IEEPA refunds on entries that are finally liquidated and past the 80-day reprocessing window
- Government position: non-litigants should not receive Phase 3 refunds

### Impact assessment

- **Phase 1 and Phase 2 refunds already paid or in process**: Not directly at risk — CBP is actively disbursing
- **Phase 3 (finally liquidated, non-litigants)**: High risk — government contesting the legal basis
- **Currently unliquidated entries (Phase 1/2 eligible)**: Lower risk — CBP processing these regardless
- **Protest entries (80–180 days)**: Still processable under statutory protest rights (19 U.S.C. §1514)

- **Rejection rate**: ~15% (confirmed, unchanged from prior reports)
- **Top rejection causes** (unchanged): line-level data mismatches, ineligible entry types, missing ACH enrollment, duplicate entries across declarations, filer authorization failures (IOR/broker check)

## Code Changes Made

**File**: `src/lib/tariff-calculator.ts`

1. Added `"cape_phase2"` to `FilingMethod` type with docstring
2. Added `isFlaggedForReconciliation?: boolean` field to `EntryForEligibility`
3. Added `applyPhase2ReconciliationFlag()` helper — promotes `cape_phase1` → `cape_phase2` for reconciliation-flagged entries and injects mandatory filing-sequence warning
4. Updated `EXCLUDED_ENTRY_TYPES` comment to clarify Phase 1/2 exclusion scope
5. Wired `applyPhase2ReconciliationFlag()` into both eligible return paths in `checkEligibility()`

**Impact**: Callers that inspect `filingMethod === "cape_phase2"` in the returned `EligibilityResult` can now route reconciliation-flagged entries to Phase 2 guidance. Entries with `isFlaggedForReconciliation: false/undefined` are unaffected.
