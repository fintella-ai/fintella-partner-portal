## Finding 1 — CAPE Phase 2 Launched June 29, 2026 (ACTIONABLE — code updated)

**Source**: CBP ACE portal deployment, multiple trade law firm confirmations  
**Refs**: [Thompson Hine SmarTrade](https://www.thompsonhinesmartrade.com/2026/06/cbp-confirms-june-29-2026-ieepa-tariff-refund-process-phase-2-launch/), [Diaz Trade Law](https://diaztradelaw.com/cape-ieepa-duty-refunds/), [Customs International Trade Law Blog](https://customsandinternationaltradelaw.com/2026/07/03/breaking-trade-news-cape-phase-ii-launches-usmca-not-renewed/)

**What changed**: On June 29, 2026, CBP deployed CAPE Phase 2, extending CAPE to cover entries of **Types 01, 02, 06** that are *flagged for reconciliation* (i.e., a reconciliation was planned but the Type 09 reconciliation entry has not yet been filed). The same 80-day liquidation window continues to apply.

**What is still excluded** (unchanged): Type 08 (Duty Deferral), Type 09 (Reconciliation entries themselves), Type 23 (TIB), Type 47 (Drawback). These remain in `EXCLUDED_ENTRY_TYPES`.

**Phase 2 metrics as of June 30**:
- 1.6 million reconciliation-flagged entries successfully filed in CAPE
- 4.36 million entries failed Phase 2's entry-level checks (likely historically-liquidated reconciliation entries — liquidated > 80 days before June 29, 2026)

**Code change made** (`src/lib/tariff-calculator.ts`):
- Added `"cape_phase2"` to the `FilingMethod` union type
- Added `isReconciliationFlagged?: boolean` field to `EntryForEligibility`
- `checkEligibility()` now routes reconciliation-flagged entries to `"cape_phase2"` instead of `"cape_phase1"`, with appropriate reason strings
