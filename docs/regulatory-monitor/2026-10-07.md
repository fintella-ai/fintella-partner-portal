## 1. CAPE Phase 3 launched October 6, 2026 ✅ UPDATED

**Source:** Multiple trade law advisories and CBP CSMS announcements  
- [CBP Confirms October 6, 2026 Launch of Phase 3 — Thompson Hine](https://www.thompsonhinesmartrade.com/2026/09/cbp-confirms-october-6-2026-launch-of-phase-3-of-the-ieepa-tariff-refund-process/)  
- [CAPE Phase 3: Who Can File for IEEPA Refunds on October 6 — Caspian](https://www.meetcaspian.com/blog/cape-phase-3-ieepa-refunds-october-6)  
- [CAPE Phase 3 Launches October 6 — Coppersmith](https://www.coppersmith.com/cape-phase-3-ieepa-refunds-october-2026/)

**What changed:**  
CAPE Phase 3 opened yesterday (October 6, 2026) for finally-liquidated entries. This is the first CAPE expansion that covers entries liquidated more than 80 days ago — previously routed to CIT litigation only.

**Eligibility:**
- Importer must be a **named plaintiff in a pending CIT IEEPA case**
- Must have provided a valid importer-of-record number to CBP **by July 30, 2026**
- Covers entries finally liquidated (past the 180-day protest window)
- Estimated pool: **$11.4 billion** (6.9% of total IEEPA tariffs collected)

**Calculator changes made:**
- `src/lib/tariff-calculator.ts`: Added `"cape_phase3"` to the `FilingMethod` union type
- `src/lib/tariff-calculator.ts`: Added `isCitPlaintiff?: boolean` field to `EntryForEligibility`
- `src/lib/tariff-calculator.ts`: `checkEligibility()` now returns `filingMethod: "cape_phase3"` (status: `"eligible"`) for finally-liquidated entries where `isCitPlaintiff === true`, rather than `"litigation"` / `"excluded_expired"`
- `src/lib/tariff-risk-score.ts`: Added `cape_phase3: 20` to `FILING_RISK` map (between protest=15 and litigation=35 — automated CBP pathway but requires active CIT plaintiff status)
- `prisma/seed-data/ieepa-tariff-rates.json`: Added `capePhase3` documentation block

**Impact on current calculator logic:**
- Entries previously routed to `"excluded_expired"` / `"litigation"` that belong to CIT plaintiffs now route to `"eligible"` / `"cape_phase3"`
- Default behavior for non-CIT-plaintiffs is unchanged
- The `isCitPlaintiff` flag must be set by the calling API route from the partner's dossier data; the default (undefined/false) preserves existing behavior
