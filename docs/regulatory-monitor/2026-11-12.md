## 6. CAPE Phase 3 — Eligibility Logic Update

**What changed in `src/lib/tariff-calculator.ts`:**

1. Added `"cape_phase3"` to the `FilingMethod` union type with updated JSDoc.
2. Added `isCitPlaintiff?: boolean` to `EntryForEligibility` interface.
3. Updated `checkEligibility()`: entries with expired protest windows (>180 days since liquidation) now return `filingMethod: "cape_phase3"` and `status: "eligible"` when `entry.isCitPlaintiff === true`, instead of `"excluded_expired"`.
4. Updated `getRoutingBucket()` to route `cape_phase3` entries to `"legal_required"` (not `"self_file"` — Phase 3 requires a court order, so legal counsel remains necessary).
5. Updated the exclusion-reason text for the non-plaintiff expired-protest path to mention Phase 3 as a potential option.

**Why:** CAPE Phase 3 launched October 6, 2026 and is operational. The calculator was routing all finally-liquidated entries to `"litigation"` / `"not_applicable"`, missing the Phase 3 path for CIT plaintiffs. With an estimated $11.4B (6.9% of total IEEPA duties) in finally-liquidated entries, this is a material omission for affected importers.
