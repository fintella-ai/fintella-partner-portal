## Findings

### 1. CAPE Phase 2 — ACTIONABLE ✅

**Source:** [CSMS #69035485 (June 23, 2026)](https://content.govdelivery.com/accounts/USDHSCBP/bulletins/41d65dd?reqfrom=share)  
**Confirmed by:** [Thompson Hine SmarTrade (June 2026)](https://www.thompsonhinesmartrade.com/2026/06/cbp-confirms-june-29-2026-ieepa-tariff-refund-process-phase-2-launch/), [International Trade Insights (June 2026)](https://www.internationaltradeinsights.com/2026/06/cbp-issues-guidance-on-june-29-2026-cape-expansion/), [Customs & International Trade Law Blog (June 26, 2026)](https://customsandinternationaltradelaw.com/2026/06/26/cape-reconciliation-refunds/)

**What changed:** CBP will deploy CAPE Phase 2 on **June 29, 2026** (tomorrow). This expands the automated IEEPA refund process to cover **entry types 01, 02, and 06 that are flagged for reconciliation**, provided:
- The corresponding Type 09 reconciliation entry has **not yet been filed**
- The underlying entry is unliquidated OR liquidated within the 80-day CAPE window

The Type 09 reconciliation entry itself **remains excluded** from CAPE in Phase 2.

**Critical client guidance surfaced:** Importers with reconciliation-flagged entries and a reconciliation deadline within 30 days should prioritize the CAPE declaration BEFORE filing the Type 09. Once the Type 09 is filed, the underlying entries are locked out of the Phase 2 automated path.

**What was updated in code (`src/lib/tariff-calculator.ts`):**
- Added `"cape_phase2"` to the `FilingMethod` union type
- Added `flaggedForReconciliation?: boolean` field to `EntryForEligibility` interface
- Added `CAPE_PHASE2_LAUNCH_DATE = new Date("2026-06-29T00:00:00Z")` constant
- Updated `checkEligibility()` to:
  - Return `excluded_type` with a "Phase 2 launches June 29" message for reconciliation-flagged entries submitted before June 29
  - Return `eligible` with `filingMethod: "cape_phase2"` for reconciliation-flagged entries on/after June 29 (same 80-day liquidation window applies)
  - Pass the reconciliation flag through to the reason string in the unliquidated path

### 2. Section 122 Tariff — Approaching Expiration ⚠️ (No Code Change)

**Sources:** [BDO (May 2026)](https://www.bdo.com/insights/tax/u-s-court-of-international-trade-invalidates-section-122-tariffs), [Skadden (May 2026)](https://www.skadden.com/insights/publications/2026/05/us-trade-court-strikes-down-section-122-tariffs), [Peacock Tariff Consulting](https://www.peacocktariffconsulting.com/section-122-expiration-tracker/)

**Status:** The CIT issued a divided ruling on **May 7, 2026** holding the Section 122 tariffs unlawful (statutory conditions not satisfied). A stay appears to be in place — tariffs continue to be collected pending appeal. The tariff expires automatically at **12:01 AM EDT July 24, 2026** (150-day statutory cap; Congress cannot unilaterally extend it). Section 301 replacement tariffs are expected to be in place by that date.

**Seed data already correct:** `S122-01` has `"endDate": "2026-07-23"` which is accurate.

**Watch for (next monitor run):** A new presidential proclamation imposing Section 301 tariffs before July 24 would require a new seed entry. No such proclamation has been issued as of today.

### 3. Euro-Notions Florida v. United States — Government Appeal (No Code Change)

**Source:** [Foley & Lardner (June 2026)](https://www.foley.com/insights/publications/2026/06/what-every-multinational-should-know-about-the-governments-appeal-of-judge-eatons-universal-ieepa-tariff-refunds-order-and-why-it-is-claiming-it-can-keep-billions-of-dolla/), [Holland & Knight (June 2026)](https://www.hklaw.com/en/insights/publications/2026/06/ieepa-tariff-refund-update-government-appeals)

**Status:** The government is appealing Judge Eaton's CIT order in *Euro-Notions Florida v. United States* requiring refunds for all IEEPA duties including finally liquidated entries. Government response was due June 25, 2026.

**CAPE Phase 3 (finally liquidated entries):** CBP testimony at June 9 hearing confirmed Phase 3 is on track for **late July 2026**. Phase 3 is available only to importers who have filed at the CIT. Current `excluded_expired` status in the calculator is appropriate for finally liquidated entries outside the protest window — the litigation path handles these.

**No code change needed.** The appeal outcome does not affect calculator eligibility logic; it affects whether CBP must issue refunds for entries that fell outside the protest window, which is handled separately via CIT dockets.
