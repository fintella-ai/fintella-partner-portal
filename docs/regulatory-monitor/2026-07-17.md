### 2. USTR Section 301 replacement — announcement expected July 20 (3 days)

USTR ran two Section 301 investigations (launched March 11) with a completion deadline of approximately **July 20, 2026**:
- **Forced-labor investigation** covering 59 countries + EU → proposed 10% (15 countries) or 12.5% (45 countries)
- **Excess manufacturing capacity** investigation covering 16 economies

Public comment period closed July 6; USTR held a public hearing July 7. No final EO has been signed as of today. If signed, this would be the effective tariff replacement for Section 122 — but under a different legal authority (Section 301 of the Trade Act of 1974), not IEEPA and not Section 122.

**Impact on calculator:** Section 301 duties are NOT IEEPA duties — no refund eligibility. The tariff refund calculator scope (IEEPA Feb 2025–Feb 2026) is unaffected. The seed data would not need new entries for Section 301 rates. However, we should note the new tariff regime in the metadata so users understand the current landscape.

**What to do when signed:** Add a metadata note to `ieepa-tariff-rates.json` explaining that Section 301 tariffs succeeded Section 122 starting [date]. No rate records needed (Section 301 is outside the calculator scope).

### 4. CAPE Phase 2 — operating since June 29, 2026

CAPE Phase 2 deployed on June 29, 2026 via CSMS # 69066837. It expanded CAPE to accept **entries flagged for reconciliation** (types 01, 02, 06) for which the reconciliation entry (Type 09) has NOT yet been filed. Requirements:
- The underlying entry must be unliquidated, or if liquidated, within 80 days of liquidation
- The Type 09 reconciliation entry must NOT be on file before the CAPE declaration
- Type 47 drawback entries remain excluded

**Impact on `checkEligibility()`:** No change required. The existing `EXCLUDED_ENTRY_TYPES = new Set(["08", "09", "23", "47"])` is correct:
- Type 09 itself is still excluded from being filed on a CAPE declaration
- Entry types 01, 02, 06 (including those flagged for reconciliation) were already eligible in the code
- Type 47 remains excluded — consistent with current code and `isDrawback` flag

**Note:** The code's `FilingMethod` type uses `"cape_phase1"` for automated CAPE submissions. This string label predates Phase 2. Consider renaming to `"cape"` in a future session to reduce confusion — but this is cosmetic, not functionally wrong.
