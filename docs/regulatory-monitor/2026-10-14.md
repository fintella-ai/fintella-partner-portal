## Finding 1: CAPE Phase 3 — Launched October 6, 2026 (ACTIONABLE)

### What happened

CBP launched CAPE Phase 3 on October 6, 2026, opening a new automated CAPE refund path for "finally liquidated" entries — entries that were definitively liquidated and therefore fell outside Phase 1's 80-day reliquidation authority.

**Phase 3 scope (per multiple broker/law firm advisories):**
- Covers entries with a **final liquidation** date (i.e., CBP cannot reliquidate under its own 80-day authority)
- Eligibility is **limited to CIT plaintiffs only** — importers who are parties to pending IEEPA suits at the Court of International Trade
- Plaintiffs must have submitted a valid IOR number to CBP by July 30, 2026; late IORs await further CBP instructions
- Legal authority: July 17, 2026 CIT order authorizing reliquidation for plaintiffs
- Source: [CH Robinson advisory (Sep 17, 2026)](https://www.chrobinson.com/en-us/resources/insights-and-advisories/client-advisories/2026q3/09-17-26-cbp-cape-phase-3-ieepa-refunds/), [Leyton US (Oct 2026)](https://leyton.com/us/insights/articles/cape-phase-3-set-to-launch-october-6-what-it-means-for-ieepa-tariff-refunds/), [Coppersmith (Oct 2026)](https://www.coppersmith.com/cape-phase-3-ieepa-refunds-october-2026/)

### What Phase 3 is NOT

- Not open to non-plaintiff importers (they still face litigation-only for finally liquidated entries)
- Type 47 (drawback) entries remain excluded — no Phase 3 eligibility confirmed
- Type 09 (reconciliation entries): existing entries with reconciliation flags (types 01/02/06) where the Type 09 rec hasn't been filed gained CAPE eligibility June 29, 2026, but Type 09 entries themselves remain excluded

### Impact on `tariff-calculator.ts`

The current `checkEligibility()` function routes all finally-liquidated entries (liquidated > 180 days ago) to:
```
status: "excluded_expired"
reason: "Protest window expired (liquidated > 180 days ago) — CIT litigation only"
filingMethod: "litigation"
```

For **CIT plaintiffs**, Phase 3 provides a CAPE path for these same entries. The current logic is **not wrong for non-plaintiffs** but is **incomplete for plaintiffs**.

**Recommended code changes (John's decision needed):**

1. Add `"cape_phase3"` to the `FilingMethod` type union
2. Add a `isCitPlaintiff?: boolean` field to `EntryForEligibility`
3. In `checkEligibility()`, before the `excluded_expired` return, check `entry.isCitPlaintiff` and route to `cape_phase3` if true
4. Update `getRoutingBucket()` to map `litigation` (for non-plaintiffs) vs `cape_phase3` (for plaintiffs) appropriately
5. Consider a `needsReview` flag for entries that are "finally liquidated and may be eligible if plaintiff" to prompt users to check their CIT status

This is a **design decision** — the calculator currently operates without knowing plaintiff status. Adding a plaintiff flag means the UI/intake flow would need a new checkbox or question.
